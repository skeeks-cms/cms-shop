# GPD: настройки и применение каталога

Текущая схема и правила: [GPD v2](gpd.md). Разделы с датами — история внедрения.

## Компонент

`gpd` (`components/GpdComponent`) наследует стандартный CMS Component и автоматически
показывается в настройках. Значения хранятся штатным cms_component_settings.
Доступ к форме предоставляет существующий административный контроллер CMS.
`forSite()` восстанавливает project defaults, выбирает сайт, исключает пользовательские
переопределения и загружает сохранённые настройки без cache на каждом запуске.

Параметры: enabled (по умолчанию0), createProducts1, updateProducts1,
excludedAction=deactivate (keep/delete),
reactivateProducts1, newProductsActive1. Ключ остаётся в skeeksSuppliersApi.
Изображения в v2 обрабатываются как в v1: разделы, бренды и новые страны скачиваются; товары, коллекции и варианты характеристик используют прежний skeeksSuppliersApi.is_download_images (по умолчанию ссылки). Настройка gpd.imageMode скрыта и не используется. Карточки и изображения складов новые jobs пока не синхронизируют: используются заранее настроенные склады. Общий переключатель управляет новыми receive/apply,
но не отключает legacy-команды автоматически на других установках.

## Применение

`shop.gpd.catalog.apply`, payload{}, очередь gpd-apply, отдельный native worker.
Ресурс shop:gpd:apply, overlap skip, timeout600, lease120, maxAttempts3,
ChunkedJobHandler с продолжением примерно через15с. Порции до10 карточек,
при batch_too_large пакет делится. Расписание60с создаётся при rollout.

Миграция m260917_120000_gpd_catalog_application добавляет в shop_gpd_catalog_state:
- applied_revision: последняя обработанная версия, включая явный пропуск защищённых полей;
- applied_at: время обработки;
- local_product_id: локальная карточка;
- deactivated_by_gpd: право автоматически восстановить активность при возврате.

Незавершённая работа определяется revision>applied_revision и needs_resolution=0.
HTTP выполняется до блокировки состояния. Версия повторно проверяется после FOR UPDATE.
Запись карточки и applied_revision коммитятся одной транзакцией. Более новая полученная
версия не затирается старым ответом. Pending/not_available не означают исключение.
При ошибке версия остаётся неприменённой; следующие расписания повторяют её,
не блокируя последующие ID. Ошибки идут в штатный itemError и CSV задания.

ShopCatalogWriter — новый сервис, legacy-контроллер не вызывается и не изменён.
Сопоставление карточек по sx_id и cms_site_id; дубли отклоняются.
Флаг is_sx_info_update защищает описательные поля, изображения, свойства и группировку.
Категории/бренды/коллекции/свойства разрешаются по sx_id через отдельный поток v2. Отсутствующие зависимости оставляют товар ожидающим до применения справочника. Страны и единицы измерения добавляются по коду через v2 без перезаписи существующих. Подробности — в gpd-reference-sync.md.

Пустые images, image, collection_ids и properties удаляют соответствующие связи;
локальные свойства без sx_id не очищаются. Группировка меняет только принадлежность
обрабатываемого товара, не отсоединяет другие защищённые или ожидающие карточки.
API не обязан удовлетворять ручной форме site's required dimensions: импорт проверяет
числовой формат, но не выдумывает положительные размеры, отсутствующие в источнике.

Изображения заготавливаются перед товарной транзакцией. При смене способа/URL
существующий общий файл не заменяется: создаётся запись с собственным external_id;
уникальный sx_id не дублируется. Кешированные ID перепроверяются: CMS удаляет файл
при снятии последней связи. Неиспользованные после сбоя загруженные файлы могут
потребовать штатной очистки хранения; транзакция БД не откатывает внешние файлы.

## Исключения

По умолчанию деактивация; фактическую политику сайта определяет excludedAction. Подробный перечень связей и сохранение справочников описаны в [gpd.md](gpd.md).
Наличие активной складской позиции другого источника (склад без sx_id) сохраняет товар.
При delete заказы, документы, история движения, локальные складские позиции и дочерние товары переводят обработку в деактивацию. Технические позиции GPD без истории удаляются атомарно с товаром; полный перечень защитных связей — в gpd.md.
Ограничение FK при удалении откатывает вложенную транзакцию и также приводит к
деактивации. Вручную выключенный товар не получает deactivated_by_gpd.
Настройка синхронизации описания не отменяет отдельную политику исключения.

Цены и остатки применяет отдельная shop.gpd.offers.sync; см. [gpd-offer-sync.md](gpd-offer-sync.md). Повторное включение
обновления защищённой карточки само по себе не изменяет источник/revision: уже
обработанная версия повторно не применяется до нового события или явной сверки.
